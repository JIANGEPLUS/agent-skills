# 实现、测试与性能

## 代码契约
遵从仓库和语言版本。明确返回值、异常/非法输入策略、是否修改输入、确定性与多解选择。不要同时给互相不一致的伪代码和实现。
注意 C++ 溢出/迭代器、Java 数值和比较器、Python 递归深度/切片复制/大整数等实际语义；不能把所有语言的运算都当常数成本。

## 分层验证
1. 样例与手工可算案例：核对输出定义。
2. 边界：空/单元素、重复、全相等、极值、无解、多解、不可达、零/负值和退化结构。
3. 小规模独立基线对拍：生成有界输入，固定种子，保留完整失败输入；不要复制候选的关键逻辑当 oracle。
4. 性质/变形测试：只用已证明适用的性质，如排序后有序且多重集不变。多解检查合法性和目标值，不强制相同排列。
5. 压力测试：隔离于生产，限制输入、时间、内存；避免指数基线跑大输入。

测试不能证明全输入正确，浮点对拍须有有根据的容差和误差尺度。发现失败尽量缩小反例，再查契约、证明和实现哪层出错。

## 性能记录
同版本、同输入和计时口径；计入/排除初始化、I/O、数据生成须注明。适当预热和重复，记录分布而非只报最好一次；内存与尾延迟按需求测。
分析复杂度只是预算，不能虚构跑分。使用 profiler 找热点后优化，复查回归；不为微小速度牺牲清晰性或正确性。

## 交付
提供实际代码、必要运行命令、依赖、测试输入/结果、复杂度和未验证项。说明这是单元测试、随机对拍、实测性能还是仅静态推导；不得统称“所有测试通过”。
