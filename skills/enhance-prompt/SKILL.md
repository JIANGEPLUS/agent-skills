# 增强提示词 Skill（Prompt Enhancement）

## 功能定位

对用户给出的原始指令做一次「改写与增强」：分析上下文、消除歧义、补全缺失要素、纠正错误，输出一条更清晰、更具体、更可执行的增强版提示词。本 skill 只负责增强提示词本身，**不执行**增强后的指令，不生成代码或交付物。

## 触发条件

满足以下任一条件时使用本 skill：

1. 用户显式要求增强/优化/改写提示词（如「增强提示词」「优化这段指令」）。
2. 用户使用 `/enhance-prompt <指令>` 形式调用。
3. 用户明确表示「先帮我改清楚这句话，先不要执行」。

注意：若用户的指令本身已足够清晰且未表达增强意图，不要主动触发本 skill。

## 工作流程

1. 读取待增强的原始指令，并结合当前会话的历史上下文理解其真实意图。
2. 逐项检查并改进以下方面：
   - **清晰度**：消除模糊表述与歧义指代（如「这个」「那个」缺少明确对象）。
   - **具体性**：补全缺失的关键要素（目标、范围、约束、期望输出格式）。
   - **正确性**：纠正事实性错误、术语误用或逻辑矛盾。
   - **可执行性**：使增强后的指令可直接作为任务指令使用。
3. 若指令中包含三反引号（```）代码块，先判断其是否为示例代码：是则**原样保留，不做改写**。
4. 立即输出增强结果。**不要调用任何工具**（不读文件、不搜索、不执行命令），即使对答案不完全确定也直接回复。

## 输出格式

严格按以下格式回复：

```
### 以下是原指令的增强版本，更加具体和清晰：
<enhanced-prompt>增强后的提示词内容</enhanced-prompt>
```

增强后的提示词写在 `<enhanced-prompt>` 标签内；除该固定格式外不附加多余解释。若原始指令存在多种合理的增强方向，可在标签内以简短分句并列说明，但仍保持单条可用指令的形态。

## 约束与注意事项

- 只增强、不执行：输出增强版提示词后即结束，不得据此开始实施任务。
- 不编造用户未提供且无法从上下文推断的需求；对必须补充的假设，在增强提示词中以「（假设：…）」形式标注。
- 保留用户原始意图，不做方向性改写（如把「写脚本」改成「建网站」）。
- 语言跟随用户：用户用中文提问则输出中文增强提示词，以此类推。

## 使用示例

```text
用户：/enhance-prompt 帮我做一个登录功能
输出：<enhanced-prompt>实现一个用户登录功能：包含邮箱+密码登录表单、前端输入校验、
登录接口调用与错误提示（密码错误/账号不存在），登录成功后跳转到首页。
技术栈沿用当前项目现有框架，UI 风格与现有页面保持一致。（假设：暂不需要第三方
OAuth 登录和记住我功能）</enhanced-prompt>

用户：/enhance-prompt 优化一下这个API
输出：<enhanced-prompt>分析当前 API 的响应时间与资源占用，找出主要性能瓶颈并给出
优化方案：包含具体瓶颈定位（如 N+1 查询、缺少索引、串行 IO）、对应的修改建议，
以及优化前后的对比指标。（假设：以「优化」指响应性能而非代码可读性）</enhanced-prompt>
```
