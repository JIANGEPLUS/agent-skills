# algorithm-modeling — 建模与选型

---

## 1. 简介

算法技能包的一个模块，负责**把业务或题面转成可被算法处理的问题定义并选定算法方向**。可独立调用，也可由 `algorithm-engineer` 总纲路由而来。

---

## 2. 职责边界

| 做什么 | 不做什么 |
|--------|---------|
| 厘清问题类型与契约、建立模型与基线、按特征选算法方向、评估复杂度预算 | 正确性证明（→ `algorithm-proof`）、代码实现与测试（→ `algorithm-implementation`）、模型训练与调参（→ `algorithm-applied`） |

---

## 3. 触发条件

如何建模 / 选什么算法 / 问题抽象 / 方案对比 / 判定-计数-最优化-构造 / 复杂度预算评估 / "能用 DP 吗""该不该用图论"。

---

## 4. 输入

问题或场景描述；可选：输入规模、数值范围、时间空间限制、输出要求、已有方案。

---

## 5. 工作流

1. 厘清问题类型：判定 / 计数 / 最优化 / 构造；静态 / 动态；在线 / 离线；精确 / 容错；是否需还原方案
2. 固定契约；缺关键约束时先问，或给条件分支
3. 建立模型 + 简单正确基线，说明瓶颈
4. 按特征选方向并检查必查前提（有序查找→二分、最优子结构→DP、局部选择→贪心、连通路径→图模型等）
5. 评估建模、数据准备与维护的总成本
6. 输出选型结论：候选方向、前提、取舍、退路

---

## 6. 输出

- 问题定义（类型、输入输出、规模、约束）
- 基线与瓶颈
- 候选方向 + 各自前提 + 取舍 + 退路
- 契约：[templates/problem-contract.md](templates/problem-contract.md)

---

## 7. 使用要点

- 选型表只提供方向，不是自动模板；同一关键词可能对应不同问题
- 确认业务约束是否真的等价于图边、容量、代价等模型假设
- 规模太大时基线只在小输入运行；生产方案优先维护性与已验证组件
- 不因"高级"而优先选某算法；先正确再性能，但及早排除明显超预算方案
